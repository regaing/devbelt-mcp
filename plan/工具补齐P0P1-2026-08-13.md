## 1. 需求概述

- **背景**：当前 63 个工具覆盖编码/加解密/代码/JSON/数据/文本/单位/网络/杂项/时间 10 族，但对比开发者日常 + AI 高频调用，仍缺 P0（8 个）+ P1（6 个，不含 code_execute）共 14 个核心能力。
- **目标**：补齐 HTTP 调试、JWT、JSONPath、二维码解码、数学计算、RSA、CSV、SSL 检查、密码哈希、端口探测、编码检测、Schema 校验、HTML 实体、密码强度共 14 个工具。
- **范围**：豪华方案（使用成熟第三方库保证能力完整），工具总数 63 → 77。
- **非目标**：不做 `code_execute`（任意代码执行，安全风险高，用户明确排除）；不涉及旧项目迁移；不新增数据库。

## 3. 方案设计

### 3.1 主推荐方案：豪华方案（14 工具 + 6 新依赖）

**整体思路**：新增 14 个工具，按族归属写入对应文件，成熟能力用权威第三方库，网络/算法类用 node 原生实现。新增依赖统一在 package.json dependencies。

### 3.2 工具清单与归属

| # | 工具名 | 族文件 | 实现方式 | 依赖 |
|---|---|---|---|---|
| 1 | `net_http_request` | net.ts | node fetch/https，支持 method/headers/body/cookies | 原生 |
| 2 | `crypto_jwt` | crypto.ts | node:crypto HMAC + base64url 自实现 | 原生 |
| 3 | `json_path` | json.ts | JSONPath 提取（`$.a[0].b` 等完整语法） | **jsonpath-plus** |
| 4 | `misc_qrcode_decode` | misc.ts | 二维码解码（本地图片路径/base64） | **jsqr** |
| 5 | `misc_calc` | misc.ts | 数学表达式计算（函数/常量/矩阵） | **mathjs** |
| 6 | `crypto_rsa` | crypto.ts | 生成密钥对/加密解密/签名验签 | 原生 |
| 7 | `data_csv` | data.ts | CSV 解析/生成/转 JSON（复用 xlsx 读，自写写） | 复用 xlsx |
| 8 | `net_ssl_check` | net.ts | 证书有效期/签发者/链（node:tls） | 原生 |
| 9 | `crypto_password_hash` | crypto.ts | bcrypt 哈希/校验 | **bcryptjs** |

### 3.4 关键接口设计

1. **net_http_request**（完整开发）
   ```
   { url, method=GET, headers?, body?, timeout=15000, follow_redirects=true,
     json?(自动 JSON 序列化), form?(multipart/form-data 文件上传) }
   → { status, headers, body(text), content_type, elapsed_ms, final_url, size }
   ```
   - 支持 `application/json` 自动序列化（传对象）
   - 支持 `multipart/form-data` 文件上传（file_path 字段）
   - 支持自定义 header/cookie、重定向控制、超时

2. **crypto_jwt**
   ```
   { token, secret, action=decode/verify }
   decode → 解 header/payload（不校验）
   verify → 校验签名 + 过期时间 + 返回 payload
   ```

3. **json_path**
   ```
   { json, path("$.data.list[0].name"), action=extract }
   ```

4. **misc_calc**
   ```
   { expr("2*(3+4)^2 / sin(pi/2)") }
   → { result, rounded }
   ```

5. **crypto_rsa**
   ```
   { action=generate/encrypt/decrypt/sign/verify, key_pem?, data, public_key?/private_key? }
   ```

6. **net_ssl_check**
   ```
   { host, port=443 }
   → { valid, days_remaining, valid_from, valid_to, issuer, subject, chain }
   ```

## 4. 测试策略（用户重点要求）

按项目约定，**开发后先做好测试**，每个工具覆盖三层：

1. **Happy path**：正常输入 → 正确输出
2. **边界**：空值/极值/格式边界（空 JSON、超长表达式、过期证书、无效 token）
3. **错误路径**：非法输入 → 可读错误文本（guard 包装）

具体测试点：
- `net_http_request`：本地 mock 服务验证 GET/POST/header/body/超时
- `crypto_jwt`：HS256 编解码 golden、篡改签名、过期 token
- `json_path`：嵌套提取、数组过滤、路径不存在
- `misc_calc`：四则/函数/常量、除零、非法表达式
- `crypto_rsa`：密钥对生成、加解密往返、签名验签
- `crypto_password_hash`：哈希/校验往返、错误密码
- `net_ssl_check`：公网证书（可跳过 CI 弱网）+ 本地无效主机
- `net_port_check`：本地起临时 server 测通、测关
- 其余：golden 回归 + 边界 + 错误

目标：83 → **约 115+ 用例**。**全部通过后才提交**（不边开发边提交，最后统一验证闭环）。

## 5. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| mathjs/ajv 体积较大 | 包 +300KB | 可接受（豪华方案既定） |
| 网络类测试依赖外网 | 测试不稳定 | 本地 mock 服务 + 外网测试标 skip 或容错 |
| RSA 密钥生成耗时 | 测试慢 | 用小密钥（1024 位）测试 |
| jsqr 解码需要图片解码 | 依赖 PNG 库 | 复用 qrcode 生成→jsqr 解码做往返测试 |
